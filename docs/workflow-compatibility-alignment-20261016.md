# Dynamic Workflow 对齐修改（2026-10-16）

用户选择保留多核心兼容：允许模型映射和 JSON 降级，但明确提示差异。本次修改 OpenClaude Desktop 自带的工作流运行器，以本地 Claude Code 2.1.280 提取代码中的预算与恢复规则为参照；不把其他核心宣称为 Claude。

## 已修改

- **共享预算**：主模型和同一会话中的独立工作流子进程共同记账；每轮用户输入保存起点。已完成工作流的消耗保留，上一轮仍运行的代理后续消耗也能被新一轮看到。嵌套工作流沿用同一计量。达到目标后停止启动新代理，已启动代理允许完成并超出目标。
- **恢复匹配**：按全局调用顺序、prompt 和脚本明确传入的七类选项匹配。宿主 cwd、权限模式、默认模型和默认 effort，以及 label/phase 等展示属性不再导致缓存失效。强制模型模式会先忽略脚本的 model 选项。
- **兼容说明**：保留模型映射、JSON 校验和重试、只读权限转换。相关说明进入事件日志，并在任务卡片的“兼容差异”中展示。普通脚本日志不混入该区域，重复提示会合并。
- **无法实现的限制**：`bashCommandClamp` 等底层无法保证的限制仍明确拒绝执行。

## 实现与迁移

`shared-budget.js` 为每个会话创建独立账本目录，每个子进程只更新自己的计数文件，先写临时文件再原子替换。读取预算时汇总最新计数并减去本轮起点；不依赖异步 IPC 消息抵达顺序。恢复产生新的贡献文件，避免覆盖已完成进程的用量。

本地 agent 缓存键由 v4 升为 v5。旧日志保留，但首次恢复不会复用旧格式 agent 结果，因此这些调用会重跑，可能重复其原有副作用。human/session 扩展不迁移。

## 验证范围

测试包括真实 fork 的 Node 工作流进程与本地协议夹具：同轮连续运行、两个运行进程实时接收主模型用量、跨轮重叠工作流、预算耗尽后不启动线程、旧缓存迁移、显式模型/Schema 改动、强制模型模式，以及 JSON 降级提示到任务卡片的数据链路。

最终 240 项测试全部通过。另有工作流恢复、运行器、结构化输出、失败恢复、权限、核心桥接、打包契约和卡片渲染回归。前端以 Vite 单独构建到工作区的 `claude-workflow-re/build-preview`，没有覆盖安装包。

组件预览使用实际 `WorkflowCard` 服务端渲染结果及其 CSS，以代表性兼容事件构造数据；已验证展开后的三类提示和布局，控制台无错误、无失败请求。这是组件夹具验证，不是已安装桌面应用的端到端验收。截图工具未返回结果，未将截图作为证据。

## 仍有区别

映射后的模型能力、JSON 文本输出协议和只读 shell 权限语义均可能与 Claude 不同；用量更新速度依赖所选核心。其他核心自带的原生工作流引擎未被替换，独立 CLI 也不会自动加入桌面会话预算。
