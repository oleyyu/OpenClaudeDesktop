参考固定为 Claude Desktop 2.37337.1。本轮继续遵照“只看源码”，没有操作图形界面或发起模型请求。

## 源码依据与适配

- `cccc2cf0a-CTtFjPG4.js` 的 `zS`（10525–10678）：根据该子会话的 `capabilities.reorderQueued` 启用 `enableQueueVsSteer`；向 `sendWithOutcome` 传子会话 `ref`、文字、UUID 和提交 `priority`。
- `ca80fca8d-vl1ck1Sv.js`（13160 起）：运行中的发送/停止按钮按 Queue / Steer 能力和草稿内容切换，提供 Queue for later 快捷键。
- `c6b8adeaf-B_NxsLR8.js`（约 1955、2328 起）：传递 priority、区分已发出请求与发送前拒绝、限制账号切换后的继续操作。
- `cf74bc599-3YM7j6aS.js`（约 6740–7300）：队列删除、取回编辑、立即发送、排序和清空等操作。

`btw-queue-store.mjs` 是本地 Codex 协议适配，**不是官方网络服务的原代码**。它把 Enter 映射到当前子会话的 `turn/steer`，把 Cmd+Enter 映射到 `thread/queue/add`。只有明确 `activeTurnNotSteerable` 拒绝才自动转为排队；不因传输异常自动再次发送。输入框沿用项目的 `SourceComposer`，队列沿用 `SourceQueuedMessages`，并解除主对话列宽限制。没有修改五份官方 CSS。

## 本轮实现

- 每个子会话独立保存队列、发送中的 steer、互斥操作、连接标识和列表读取版本。请求不读取主会话输入、模型、权限或队列。
- 队列读取遍历分页；过时读取不覆盖更新的结果。支持删除、取回编辑、上下调整/拖动排序、Clear all 和 Send now。
- Clear all 顺序删除点击时的条目，保留操作过程中新增的消息；已被核心消费的条目不会重复恢复。
- Send now 明确被拒绝后重新排队并恢复原顺序。重新排队已成功但排序失败时，不再把同一条消息恢复成草稿。
- Steer 接受回执、送达事件和完成事件允许不同到达顺序。已送达的消息不恢复；被停止且未送达的文字只追加到对应子会话草稿。一条没有 clientId 的送达记录只确认一个相同文字的待发消息。
- `steer-turn.cjs` 对带 expected 的请求使用原连接，校验异步准备后的连接身份；不初始化替代客户端。已经接受的请求不会因后续记录失败被当成需要重发。
- 队列操作进行时，暂时禁止关闭该子会话页签。旧连接的队列快照不会出现在新连接中。

## 范围边界

这是文字输入主路径的宿主适配，`layout-08` 仍为部分实现。子输入框尚未接入完整附件编辑；其他窗口放入的附件队列项不能在这里取回编辑或立即发送，以免丢失附件，应打开该会话处理。队列外观仍使用既有本地适配组件，当前官方新增的 seeded / waitingLane / 已送达淡出等全部展示分支没有在本轮完成。

完整跨窗口协议、服务与实验开关，以及其余审计项仍需继续。入口焦点时效与原生 Plan 实施接续在后续阶段已接入，见 [焦点与 Plan 接续](btw-focus-plan-source-20261016.md)，Plan 关闭生命周期仍未对齐。测试及构建通过不代表整套新版前端完全一致。
