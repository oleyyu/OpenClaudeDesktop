本轮只检查本地官方源码，运行模拟 RPC/事件、服务端渲染和构建，没有操作图形界面或调用模型。旧版源代码备份保持不变。

## 官方依据与本地协议边界

桌面包 `index.chunk-BU5PdZBi.js` 的 `ft` 仅在 `isSettledSideSession` 为真时自动归档 `/btw` 子会话。`index.chunk-BolytlRP.js` 的 `sideSessionSettled` / `sideSessionBusy` 明确排除固定会话、运行或启动中、存在可能丢失的工作、权限审批及用户对话等待；另有 PR 与后代会话级联条件。渲染包 `cccc2cf0a` 的 `FT` 则禁止关闭运行中或正在启动的页签。

原生 Codex 的 Plan turn 完成后，确认卡由宿主生成，并不存在官方 Claude 的挂起 ExitPlanMode 请求。因此这里仍是明确的协议适配：不能仅凭 thread 的 idle 状态判定可归档。

## 实现

- 后端在自动归档前读取子会话最新的自有 turn。分页历史使用 `thread/turns/list` 的 full 视图，必要时用 `thread/items/list` 补齐；legacy 使用自己的完整历史。父会话继承内容不参与确认。
- 有待确认计划、历史缺失/不完整、仍在运行，或检查中有新事件/元数据变化时，保留子会话。读取失败同样不会继续归档。固定会话和仍有排队消息的子会话也会保留。
- Stay in Plan 新增宿主 `btw-session / plan-stay` 操作，重新验证子会话、连接、turn、审批和队列，并取得与关闭/发送共用的子会话锁。只在验证成功后保存 `btw.planAnsweredTurnId` 并发布现有 sidebar-state 元数据快照。不发送模型消息，不更改父会话或权限。
- 相同回答可重复确认；过时 turn、已归档/分离会话、连接替换以及检查期间的新 turn 会被拒绝。保存后的回答可在重新打开、重启或另一窗口的元数据更新后恢复；新计划仍需重新确认。
- 前后端共用原来的 native `planHandoff` 判定，原有主会话行为保持一致。实施被核心接受后仍通过既有 `prepareTurn` 保存子会话权限和新 turn。
- 界面等待保存成功才记下 Stay；失败继续展示确认卡。页签关闭保护与 composer 的 sending 状态分开，避免保护页签时意外隐藏确认卡。关闭整个窗格仍可执行，后端保留未决会话以供再次打开。
- 异步发送及计划操作按连接 epoch 隔离；旧连接的完成不会清除新连接的忙状态或覆盖新回答。
