逐条结论（先复核是否真实存在，再修；依据一律是 docs/computer-use-official-spec-20261021.md 与 reference/installed-2.42304.0-20261017 源码）：

1. **【真实，已修】退避窗口里的停止会丢失**。复核：`executor.deliver` 的 3×200 ms 重试之间不看 signal / 显示锁；原生 `GlobalKeys.begin()` 无条件把 `aborted` 清回 false，确实会让 Stop / Esc 之后的重试照常打字、按住 hold、补发点击或 ⌘V。修法：
   - `executor.cjs deliver(raw, {wait, stopped})`：每次尝试（含第一次）之前问 `stopped()`，为真就不再调原生，直接返回 `{outcome:"unsupported", reasonCode:"aborted", delivered:false}`（带上一回的进度计数）。
   - `service.cjs` 新增 `displayStopped(sessionId, signal)` = 工具调用已中止 **或** 本会话不再持有显示锁（条上的 Stop、用户 Esc、回合结束、release_full_control 都会放锁）。键盘（`displayKeyboard`）、指针（`displayPointer` 的全部 `post`，现在也接收 `signal`；`displayPointerTool` 传 `ctx.signal`）、粘贴 ⌘V（`pasteText`）三条路径都走它；键盘在 Escape 守卫就绪后、调原生前再查一次。
   - 原生 `DisplayKeys.swift`：中止按操作代号 `opId`。`begin(opId)` 只有在该代号已被中止时才保持中止（不再无条件清除）；`abort(opId)` 记住该代号（最近 64 个）并在它正运行时立刻中止；不带代号的 `abort()`（显示锁释放时 `releaseHeldMouse` 用）中止正在运行的操作并记住它的代号。`Bridge.swift` 的 `hidKey/hidKeyHold/hidType/hidKeyAbort` 透传 `opId`。JS 每次 `displayKeyboard` 生成一个代号，所有重试共用。
   - `displayKeyboard` 拿到结果后**先**看 `signal.aborted` / `reasonCode==="aborted"`，再看 `outcome`。

    从图标起拖会被 `system_drag_session` 拒绝——拖文件本来就是系统拖拽会话，与用户要求一致；列表视图行（`AXRow` / `AXTextField`）不受影响。

    菜单栏规则处理（跟前台应用），只有其他层的窗口才归 Finder。
  - 右键拒绝前不另调原生 windowOwner 核对窗口归属（官方 `Y()` 会核对）；本 build 的 window_id 已由该会话的截图状态约束，坐标 / element_index 也按那张截图校验。
